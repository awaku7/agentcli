# WEB_UI_LOGGING (Web UI log/message paths)

This document explains how `src/uagent/web.py` routes output to the Web UI.

Two channels:

- **log path**: stdout/stderr are captured and streamed via WebSocket as `type="log"`
- **message path**: chat messages are sent as `type="message"` / initial payload `type="init"`

Note:

- The Web UI may suppress some CLI-specific guide lines to reduce noise.
- `[STATE] ...` lines from stderr are filtered on the log path; status is delivered via `type="status"`.
- CLI streaming uses `core.print_stream_delta()` so status lines do not split assistant text mid-line.

## 1. Message paths

The Web UI receives two main kinds of events:

- `log`: stdout/stderr-oriented operational output
- `message` / `init`: conversation messages and initial state

The browser should not infer conversation history from log events. Conversation history is represented by the message stream and the session history structures.

## 2. History and messages

`history` is the persisted/session-level record used to reconstruct a conversation. `messages` is the current message list sent through the LLM flow. Startup messages, tool results, and user/assistant messages must be classified consistently so that a WebSocket reconnect does not duplicate or omit content.

## 3. Suppressing multiline guidance

If a multiline instruction or welcome message is already represented by a dedicated message event, do not emit a duplicate copy through the `log` path. Apply the suppression on both paths when the same guidance is generated by startup or reconnect handling.

## 4. Troubleshooting

When a multiline notice still appears twice, inspect the WebSocket event type first, then check whether the same text is emitted once through stdout/stderr and once through the conversation-message path. Verify the initial `init` payload and the subsequent `message` events separately.

## 5. Related implementation

The behavior is shared by the Web UI startup/history initialization and the runtime logging path. Changes should be tested with a fresh session, a reconnect, and a history reload.
