# การบีบอัดบริบทและบริบทโมเดลที่มีขอบเขต

uag ใช้หลายชั้นเพื่อรักษาบริบทโมเดลที่กำลังทำงานให้มีขอบเขต เป้าหมายคือเพื่อลดโทเคนอินพุตที่ไม่จำเป็น โดยไม่ลบไฟล์ ผลลัพธ์ของเครื่องมือ หรือข้อมูลเซสชันที่ผู้ใช้อาจยังต้องการ

เอกสารนี้อธิบายการนำไปใช้ในปัจจุบัน นอกจากนี้ยังแยกแยะพฤติกรรมแบบกำหนดได้ (deterministic) จากพฤติกรรมที่ขึ้นอยู่กับผู้ให้บริการ (provider-specific) หรือพฤติกรรมที่ได้รับการสนับสนุนจาก LLM

## 1. พื้นผิวเครื่องมือแบบไดนามิก

ไม่จำเป็นต้องส่งนิยามเครื่องมือทุกตัวไปยังโมเดลในทุกรอบ

- `tool_catalog` ค้นหาความสามารถที่มีอยู่
- `tool_load` เปิดใช้งานเฉพาะเครื่องมือที่จำเป็นสำหรับงานปัจจุบันเท่านั้น
- `tool_catalog`, `tool_load`, และ `unload_tool` ยังคงใช้งานได้ต่อไปในฐานะเครื่องมือจัดการ
- กระบวนการ Responses API ที่เข้ากันได้กับ GPT-5.4 สามารถใช้ Tool Search ด้านเซิร์ฟเวอร์แบบเนทีฟได้
- โหมด Tool Search แบบเดิมจะจำกัดข้อกำหนดของเครื่องมือด้วย `tool_catalog` บนฝั่งไคลเอนต์

ซึ่งช่วยลดจำนวนโทเคนอินพุตที่สคีมาเครื่องมือใช้ โดยเฉพาะในระบบที่มีการติดตั้งเครื่องมือจำนวนมาก

## 2. ผลลัพธ์เครื่องมือแบบข้อความที่มีขนาดใหญ่จะกลายเป็น Artifacts

เมื่อผลลัพธ์เครื่องมือแบบข้อความเกินเกณฑ์ Artifact, uag จะเก็บผลลัพธ์ทั้งหมดเป็น Artifact และส่งการอ้างอิงแบบจำกัดและตัวอย่างให้โมเดลแทนที่จะส่งข้อความเต็ม

ค่าจำกัดเริ่มต้นคือ:

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

รูปแบบที่โมเดลสามารถมองเห็นได้ประกอบด้วยชื่อเครื่องมือ ความยาวต้นฉบับ การอ้างอิง `artifact://` เส้นทางการจัดเก็บ และตัวอย่างที่มีขอบเขต ผลลัพธ์เต็มยังคงสามารถเข้าถึงได้ผ่านที่เก็บ Artifact

สามารถปรับค่าขีดจำกัดได้ด้วย `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS` ค่า `0` จะปิดการใช้งานการส่งเสริม Artifact `UAGENT_TOOL_RESULT_MAX_CHARS` ควบคุมนโยบายผลลัพธ์ที่มีขอบเขตตามปกติ; ค่า `0` จะปิดการใช้งานขีดจำกัดตามปกตินั้น

## 3. การดึงข้อมูล Artifact ที่มีขอบเขต

เครื่องมือโครงสร้างพื้นฐาน `artifact_read` จะดึงข้อมูลเฉพาะส่วนที่ร้องขอของ Artifact เท่านั้น:

- `start_line` เลือกบรรทัดแรก
- `max_lines` ถูกจำกัดไว้ที่ 500 บรรทัด
- `max_chars` ถูกจำกัดไว้ที่ 50,000 ตัวอักษร
- สามารถใช้ทั้ง ID ของ Artifact และ URI ของ `artifact://` ได้

สิ่งนี้ทำให้สามารถตรวจสอบช่วงข้อมูลที่เกี่ยวข้องขนาดเล็กได้ แทนที่จะต้องส่งไฟล์หรือผลลัพธ์คำสั่งทั้งหมดกลับเข้าสู่รอบการทำงานของโมเดลครั้งต่อไป

อาร์ติแฟกต์ใหม่จะถูกจัดเก็บไว้ด้านล่าง:

```text
~/.uag/artifacts/
```

เส้นทาง Artifact แบบเก่าที่มีอยู่ยังคงอ่านได้เพื่อความเข้ากันได้

## 4. การแยกส่วนข้อมูลไบนารี

ข้อมูลไบนารีที่แทรกในตัวข้อความจะไม่ถูกส่งเป็นผลลัพธ์แบบข้อความไปยังรอบการทำงานของโมเดลถัดไป Base64-shaped fields ถูกแทนที่ด้วยตัวบ่งชี้สั้น เช่น:

```text
[binary payload omitted from LLM context]
```

ส่วนติดต่อผู้ใช้ (UI) และไคลเอนต์ระยะไกลยังคงสามารถรับไฟล์แนบในหน่วยความจำได้ และไฟล์ที่บันทึกไว้ยังคงสามารถเข้าถึงได้ผ่านเส้นทางหรือการอ้างอิง Artifact ของพวกมัน สิ่งนี้ช่วยป้องกันไม่ให้รูปภาพ เสียง ภาพหน้าจอ และข้อมูลไบนารีอื่น ๆ ทำให้บริบทของโมเดลข้อความมีขนาดใหญ่เกินไป

ข้อมูลไบนารีประเภทเดียวกันจะถูกทำความสะอาดก่อนการเก็บถาวรใน SQLite และ JSONL เพื่อป้องกันไม่ให้มันถูกส่งกลับมาเป็นข้อมูลขนาดใหญ่หลังการโหลดเซสชันใหม่

## 5. การบีบอัดประวัติอัตโนมัติ

uag สามารถบีบอัดประวัติการสนทนาเก่าได้เมื่อจำนวนข้อความหรือจำนวนโทเค็นที่ประมาณการถึงขีดจำกัดที่กำหนดไว้

นโยบายการบีบอัดใช้:

- จำนวนข้อความที่ไม่ใช่ระบบ;
- หน้าต่างบริบทที่แก้ไขแล้วของโมเดล (หากมี);
- `UAGENT_SHRINK_KEEP_LAST` (ค่าเริ่มต้นคือ 20);
- `UAGENT_SHRINK_MAX_TOKENS` หรือการกำหนดค่าทับที่เฉพาะสำหรับโมเดล;
- `UAGENT_SHRINK_CNT`; และ
- `UAGENT_SHRINK_RATIO` (ค่าเริ่มต้นคือ 0.5 เมื่อทราบหน้าต่างบริบท).

สามารถกำหนดขีดจำกัดเฉพาะโมเดลได้ดังนี้:

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

สรุปก่อนหน้านี้จะไม่ถูกสร้างใหม่ในทุกรอบ ปรากฏการณ์ฮิสเทอรีซิส (hysteresis) ต้องการให้ประวัติใหม่สะสมเพียงพอ หรือเกิดการล้นของงบประมาณโทเคนอีกครั้ง ก่อนที่การบีบอัดจะทำงานใหม่

## 6. LLM-assisted history summaries

เมื่อการบีบอัดอัตโนมัติใช้ LLM ข้อความเก่าจากผู้ใช้ ผู้ช่วย และเครื่องมือจะถูกสรุปเป็นข้อความระบบแบบต่อเนื่อง (rolling system message) ในขณะที่ส่วนท้ายล่าสุดยังคงถูกเก็บไว้

ประวัติที่ยาวสามารถสรุปเป็นชิ้นๆ ได้ การควบคุมที่เกี่ยวข้องคือ:

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

การสรุปจะถูกพับไปข้างหน้าแทนที่จะสร้างลำดับข้อความสรุปที่ไม่มีขีดจำกัด นี่เป็นกระบวนการที่ได้รับการสนับสนุนจาก LLM และอาจต้องการคำขอเพิ่มเติมจากผู้ให้บริการ

## 7. การบีบอัดแบบ fallback ที่กำหนดได้

หากไม่สามารถใช้สรุป LLM ได้ uag สามารถเก็บข้อความระบบส่วนต้นและข้อความล่าสุดเท่านั้น ขอบเขตการเรียกเครื่องมือจะถูกซ่อมแซมเพื่อให้ประวัติที่ได้ไม่เริ่มต้นหรือสิ้นสุดด้วยการเรียกเครื่องมือที่ถูกทิ้งไว้

ตัวโหลดและตัวทำความสะอาดยังลบรายการที่ไม่เกี่ยวข้องกับโมเดลหรือรายการที่ไม่ถูกต้องออกด้วย รวมถึงข้อความเฉพาะ UI ข้อความควบคุมภายใน บรรทัดบันทึกที่เสียหาย บทบาทที่ไม่ได้รับการสนับสนุน ผลลัพธ์เครื่องมือที่ถูกทิ้งไว้ และบล็อกการเรียกเครื่องมือที่ไม่สมบูรณ์

เมื่อเซสชันถูกโหลดใหม่ คำสั่งระบบปัจจุบันจะถูกคืนค่า และจะเก็บไว้เฉพาะข้อความระบบที่ถูกฉีดเข้ามาที่เกี่ยวข้อง เช่น บริบทของทักษะหรือฮุค

## 8. การกู้คืนเมื่อบริบทล้น

หากผู้ให้บริการรายงานว่าหน้าต่างบริบทถูกเกินขีดจำกัด uag จะระบุข้อความประวัติล่าสุดที่มีขนาดใหญ่ และย้อนกลับข้อความนั้นพร้อมทั้งประวัติที่ตามมา ก่อนที่จะลองใหม่ นี่เป็นกลไกสำรองแบบตอบสนอง ไม่ใช่การแทนที่การจัดการงบประมาณปกติ

## 9. การต่อต่อและบีบอัดข้อมูลด้านผู้ให้บริการ

ในกรณีที่ได้รับการสนับสนุน Responses API จะใช้ `previous_response_id` เพื่อต่อต่อสายการตอบกลับโดยไม่ส่งประวัติการตอบกลับทั้งหมดที่ผู้ให้บริการจัดการจากฝั่งลูกค้าอีกครั้ง

การไหลของ Responses API ยังส่งการกำหนดค่าการบีบอัดด้านผู้ให้บริการโดยใช้เกณฑ์การบีบอัดท้องถิ่นเดียวกัน พฤติกรรมที่แน่นอนขึ้นอยู่กับผู้ให้บริการ; Artifact ท้องถิ่นและนโยบายประวัติยังคงเป็นมาตรการป้องกันที่ไม่ขึ้นกับผู้ให้บริการ

## 10. ประสิทธิภาพการนับโทเคน

จำนวนโทเคนที่ใช้ในการตัดสินใจการบีบอัดจะถูกเก็บไว้ในแคชและอัปเดตแบบเพิ่มทีละน้อยเมื่อมีข้อความใหม่ถูกเพิ่มเข้ามาเท่านั้น สิ่งนี้ไม่ลดขนาดบริบทของโมเดลโดยตรง แต่ช่วยลดค่าใช้จ่าย CPU และความล่าช้าในการตัดสินใจว่าเมื่อใดจำเป็นต้องทำการบีบอัด

## สิ่งที่ยังไม่เป็นชั้นรวมที่สมบูรณ์

การดำเนินการในปัจจุบันยังไม่ได้จัดให้ทุกองค์ประกอบต่อไปนี้ในรูปของผู้จัดการที่เป็นกลางต่อผู้ให้บริการ:

- `ContextManager` และ `ContextBudget` ที่รวมเป็นหนึ่ง;
- `ToolResultRecord` ที่มีข้อมูลเมตาเกี่ยวกับความสำคัญและการลบข้อมูล;
- สรุปเชิงความหมายที่ไม่ต้องการ LLM;
- การเรียกคืนและฉีดกลับ Artifacts ที่เกี่ยวข้องโดยอัตโนมัติ;
- ผู้จัดการผลลัพธ์ (Result Manager) กลางที่รับประกันการแปลง Artifact สำหรับเครื่องมือทุกชนิดที่สร้างไฟล์ไบนารี; หรือ
- การลบออกที่คำนึงถึงลำดับความสำคัญในทุกหมวดหมู่ของระบบ ประวัติ สคีมาเครื่องมือ และผลลัพธ์

สรุปแล้ว uag ในปัจจุบันรวมการตัดทอนแบบกำหนดได้ การอ้างอิง Artifact การแยกตัวไบนารี การเลือกเครื่องมือแบบไดนามิก สรุปประวัติ การต่อเนื่องของผู้ให้บริการ และการกู้คืนเมื่อเกิดการล้น แผนงานการออกแบบสำหรับชั้นบริบทแบบรวมถูกบันทึกไว้ใน [UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md).
