# 컨텍스트 압축 및 제한된 모델 컨텍스트

uag은 여러 계층을 사용하여 활성 모델 컨텍스트를 제한된 범위로 유지합니다. 목표는 사용자가 여전히 필요로 할 수 있는 파일, 공구 결과 또는 세션 데이터를 제거하지 않으면서 불필요한 입력 토큰을 줄이는 것입니다.

이 문서는 현재 구현 내용을 설명합니다. 또한 결정론적 동작과 공급자별 동작 또는 LLM 지원 동작을 구분합니다.

## 1. 동적 도구 표면

모든 턴마다 모든 도구 정의를 모델로 전송할 필요는 없습니다.

- `tool_catalog`는 사용 가능한 기능을 검색합니다.
- `tool_load`는 현재 작업에 필요한 도구만 활성화합니다.
- `tool_catalog`, `tool_load` 및 `unload_tool`은 관리 도구로 계속 사용할 수 있습니다.
- GPT-5.4과 호환되는 Responses API 흐름은 네이티브 서버 측 Tool Search를 사용할 수 있습니다.
- 레거시 Tool Search 모드는 클라이언트 측에서 `tool_catalog`를 사용하여 도구 사양을 좁힙니다.

이를 통해 특히 도구가 많은 설치 환경에서 도구 스키마가 사용하는 입력 토큰 수가 줄어듭니다.

## 2. 대용량 텍스트 기반 도구 결과가 아티팩트로 변환됩니다

텍스트 기반 도구 결과가 Artifact 임계값을 초과하면, uag은 전체 결과를 Artifact로 저장하고, 모델에는 전체 텍스트 대신 제한된 참조 및 미리보기를 전송합니다.

기본 제한값은 다음과 같습니다.

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

모델이 볼 수 있는 표현에는 도구 이름, 원본 길이, `artifact://` 참조, 저장 경로 및 제한된 미리보기가 포함됩니다. 전체 결과는 Artifact 저장소를 통해 계속 이용할 수 있습니다.

임계값은 `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS`을 사용하여 변경할 수 있습니다. 값을 `0`으로 설정하면 Artifact 승격이 비활성화됩니다. `UAGENT_TOOL_RESULT_MAX_CHARS`는 일반적인 제한된 결과 정책을 제어하며, `0`으로 설정하면 해당 일반 제한이 비활성화됩니다.

## 3. 제한된 Artifact 검색

`artifact_read` 인프라 도구는 Artifact에서 요청된 부분만 검색합니다:

- `start_line`은 첫 번째 줄을 선택합니다.
- `max_lines`는 500줄로 제한됩니다.
- `max_chars`는 50,000자로 제한됩니다.
- Artifact ID와 `artifact://` URI를 모두 사용할 수 있습니다.

이를 통해 전체 파일이나 명령어 결과를 다음 모델 실행 단계에 다시 주입하는 대신, 관련성이 있는 작은 범위만 검사할 수 있습니다.

새로운 아티팩트는 아래에 저장됩니다:

```text
~/.uag/artifacts/
```

호환성을 위해 기존의 레거시 Artifact 경로는 계속 읽을 수 있습니다.

## 4. 바이너리 페이로드 격리

인라인 바이너리 데이터는 텍스트 형태의 도구 결과로 다음 모델 실행 단계로 전송되지 않습니다. Base64 형식의 필드는 다음과 같은 짧은 마커로 대체됩니다:

```text
[LLM 컨텍스트에서 생략된 바이너리 페이로드]
```

UI와 원격 클라이언트는 여전히 메모리 내 첨부 파일을 수신할 수 있으며, 저장된 파일은 해당 경로나 Artifact 참조를 통해 계속 사용할 수 있습니다. 이를 통해 이미지, 오디오, 스크린샷 및 기타 바이너리 페이로드가 텍스트 기반 모델 컨텍스트를 부풀리는 것을 방지합니다.

동일한 종류의 바이너리 페이로드는 SQLite 및 JSONL에 저장되기 전에 정제되어, 세션 재로딩 후 대용량 페이로드로 반환되는 것을 방지합니다.

## 5. 자동 기록 압축

uag은 메시지 수나 예상 토큰 수가 구성된 한도에 도달하면 오래된 대화 기록을 압축할 수 있습니다.

압축 정책은 다음을 사용합니다:

- 비시스템 메시지 수;
- 가능한 경우 모델의 해결된 컨텍스트 윈도우;
- `UAGENT_SHRINK_KEEP_LAST`(기본값 20);
- `UAGENT_SHRINK_MAX_TOKENS` 또는 모델별 재정의 값;
- `UAGENT_SHRINK_CNT`; 그리고
- `UAGENT_SHRINK_RATIO`(컨텍스트 윈도우가 알려진 경우 기본값 0.5).

모델별 제한값은 다음과 같이 지정할 수 있습니다:

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

이전 요약은 매 턴마다 재생성되지 않습니다. 히스테리시스(hysteresis)로 인해 압축이 다시 실행되기 전에는 충분한 새로운 이력이 누적되거나, 토큰 예산이 다시 초과되어야 합니다.

## 6. LLM 기반 기록 요약

자동 압축이 LLM을 사용할 경우, 오래된 사용자, 어시스턴트 및 도구 메시지는 롤링 시스템 메시지로 요약되며, 최근 기록은 그대로 유지됩니다.

긴 기록은 청크 단위로 요약될 수 있습니다. 관련 제어 옵션은 다음과 같습니다:

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

요약은 무한한 요약 메시지 시퀀스를 생성하는 대신 앞으로 접혀집니다. 이는 LLM이 지원하는 작업이며, 추가적인 제공자 요청이 필요할 수 있습니다.

## 7. 결정론적 대체 압축

LLM 요약이 사용할 수 없는 경우, uag은 선행 시스템 메시지와 가장 최근의 메시지만 유지할 수 있습니다. 결과 히스토리가 고아 도구 호출로 시작하거나 끝나지 않도록 도구 호출 경계가 복구됩니다.

로더와 산티라이저(sanitizer)는 또한 UI 전용 메시지, 내부 제어 메시지, 손상된 로그 줄, 지원되지 않는 역할, 고아 도구 결과 및 불완전한 도구 호출 블록을 포함하여 모델과 무관하거나 유효하지 않은 항목을 제거합니다.

세션을 다시 불러올 때, 현재 시스템 프롬프트가 복원되며 스킬 또는 훅 컨텍스트와 같이 관련성이 있는 주입된 시스템 메시지만 유지됩니다.

## 8. 컨텍스트 오버플로 복구

프로바이더가 컨텍스트 윈도우를 초과했다고 보고하면, uag은 최근의 큰 크기 히스토리 메시지를 식별하여 해당 메시지와 그 뒤따르는 히스토리를 롤백한 후 재시도합니다. 이는 반응형 대체 메커니즘이며, 일반적인 할당량 관리 방식을 대체하는 것은 아닙니다.

## 9. 제공자 측 연속 처리 및 압축

지원되는 경우, Responses API은 `previous_response_id`를 사용하여 클라이언트 측에서 제공자가 관리하는 전체 응답 이력을 다시 전송하지 않고도 응답 체인을 계속 이어갑니다.

Responses API 흐름은 또한 동일한 로컬 축소 임계값을 사용하여 공급자 측 압축 구성을 전송합니다. 정확한 동작은 공급자에 따라 다르며, 로컬 Artifact 및 기록 정책은 공급자와 무관한 안전 장치로 유지됩니다.

## 10. 토큰 계수 효율성

압축 결정에 사용되는 토큰 개수는 캐시되며, 새로운 메시지만 추가된 경우에만 점진적으로 업데이트됩니다. 이는 모델 컨텍스트를 직접적으로 줄이지는 않지만, 압축이 필요한 시점을 결정하는 데 드는 CPU 비용과 지연 시간을 줄여줍니다.

## 아직 완전한 통합 레이어가 아닌 부분

현재 구현은 다음 항목들을 모두 하나의 공급자 중립적 관리자로 제공하지는 않습니다:

- 통합된 `ContextManager` 및 `ContextBudget`;
- 중요도 및 제거 메타데이터를 포함하는 `ToolResultRecord`;
- `LLM`을 필요로 하지 않는 의미론적 요약;
- 관련 아티팩트의 자동 검색 및 재삽입;
- 모든 바이너리 생성 도구에 대해 `Artifact` 변환을 보장하는 중앙 결과 관리자; 또는
- 모든 시스템, 이력, 도구 스키마 및 결과 범주에 걸친 우선순위 기반 제거.

요약하자면, uag은 현재 결정론적 절단, Artifact 참조, 바이너리 격리, 동적 도구 선택, 기록 요약, 제공자 연속성 및 오버플로 복구 기능을 결합하고 있습니다. 통합 컨텍스트 계층에 대한 설계 로드맵은 [UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md)에 문서화되어 있습니다.
