# コンテキスト圧縮と境界付きモデルコンテキスト

uag では、アクティブなモデルコンテキストを境界内に収めるために、いくつかのレイヤーを使用しています。 その目的は、ユーザーが依然として必要とする可能性のあるファイル、ツールの結果、またはセッションデータを削除することなく、不要な入力トークンを削減することです。

このドキュメントでは、現在の実装について説明します。また、決定論的な挙動と、プロバイダ固有の挙動や LLM による支援を受けた挙動とを区別しています。

## 1. 動的なツールサーフェス

すべてのツール定義を、毎ターンモデルに送信する必要はありません。

- `tool_catalog` は利用可能な機能を検索します。
- `tool_load` は、現在のタスクに必要なツールのみを有効にします。
- `tool_catalog`、`tool_load`、および `unload_tool` は、管理ツールとして引き続き利用可能です。
- GPT-5.4 互換の Responses API フローでは、ネイティブなサーバーサイドの Tool Search を使用できます。
- レガシー Tool Search モードでは、クライアント側で `tool_catalog` を使用してツールの仕様を絞り込みます。

これにより、特に多数のツールがインストールされている環境において、ツールスキーマが使用する入力トークンの数が削減されます。

## 2. 大規模なテキスト形式のツール結果がアーティファクトになる

テキスト形式のツール結果が Artifact の閾値を超えると、uag は結果全体を Artifact として保存し、モデルには全文ではなく、範囲指定された参照とプレビューを送信します。

デフォルトの制限は以下の通りです：

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

モデルが認識できる表現には、ツール名、元の長さ、`artifact://` 参照、保存パス、および範囲指定されたプレビューが含まれます。 完全な結果は、Artifact ストアを通じて引き続き利用可能です。

しきい値は `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS` で変更できます。値を `0` に設定すると、Artifact のプロモーションが無効になります。`UAGENT_TOOL_RESULT_MAX_CHARS` は通常の範囲制限ポリシーを制御し、`0` に設定するとその通常の制限が無効になります。

## 3. 範囲指定による Artifact の取得

`artifact_read` インフラストラクチャツールは、Artifact の中から要求された部分のみを取得します：

- `start_line` は最初の行を選択します。
- `max_lines` の上限は 500 行です。
- `max_chars` の上限は 50,000 文字です。
- Artifact ID と `artifact://` URI の両方が使用可能です。

これにより、ファイル全体やコマンドの結果を次のモデル実行に再投入する代わりに、関連する小さな範囲のみを検査することが可能になります。

新しいアーティファクトは以下に保存されます：

```text
~/.uag/artifacts/
```

互換性を確保するため、既存のレガシー Artifact パスは引き続き読み取り可能です。

## 4. バイナリペイロードの分離

インラインのバイナリデータは、テキスト形式のツール結果として次のモデルターンに送信されません。 Base64形式のフィールドは、次のような短いマーカーに置き換えられます：

```text
[LLMコンテキストからバイナリペイロードが省略されました]
```

UIおよびリモートクライアントは引き続きメモリ内の添付データを受信でき、保存されたファイルはパスまたはArtifact参照を通じて利用可能です。 これにより、画像、音声、スクリーンショット、その他のバイナリペイロードによって、テキスト形式のモデルコンテキストが肥大化するのを防ぎます。

同じ種類のバイナリペイロードは、SQLite および JSONL への永続化の前にサニタイズされるため、セッションの再読み込み後に大きなペイロードとして返されるのを防ぎます。

## 5. 履歴の自動圧縮

uag は、メッセージ数または推定トークン数が設定された制限に達した場合、古い会話履歴を圧縮できます。

圧縮ポリシーでは以下を使用します：

- 非システムメッセージの数；
- 利用可能な場合、モデルの解決済みコンテキストウィンドウ；
- `UAGENT_SHRINK_KEEP_LAST`（デフォルトは 20）；
- `UAGENT_SHRINK_MAX_TOKENS` またはモデル固有の上書き設定；
- `UAGENT_SHRINK_CNT`；および
- `UAGENT_SHRINK_RATIO`（コンテキストウィンドウが判明している場合のデフォルトは 0.5）。

モデル固有の上限は、次のように指定できます：

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

以前の要約は、毎ターン再生成されるわけではありません。 ヒステリシスにより、圧縮が再度実行されるには、十分な新しい履歴が蓄積されるか、あるいはトークン予算が再びオーバーフローする必要があります。

## 6. LLM を利用した履歴要約

自動圧縮で LLM を使用する場合、古いユーザー、アシスタント、およびツールからのメッセージはローリング方式のシステムメッセージに要約され、最近のメッセージは保持されます。

長い履歴は、チャンク単位で要約することができます。 関連する制御設定は以下の通りです：

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

要約は、無制限の要約メッセージシーケンスを作成するのではなく、前方へ折り畳まれます。 これは LLM による支援操作であり、追加のプロバイダリクエストが必要になる場合があります。

## 7. 決定論的フォールバック圧縮

LLM による要約が利用できない場合、uag は先頭のシステムメッセージと最新のメッセージのみを保持することができます。 ツール呼び出しの境界は修復され、結果として得られる履歴が孤立したツール呼び出しで始まったり終わったりすることがないようにします。

また、ローダーとサニタイザーは、UI 専用のメッセージ、内部制御メッセージ、破損したログ行、サポートされていないロール、孤立したツール結果、不完全なツール呼び出しブロックなど、モデルに関係のない、または無効なエントリを削除します。

セッションが再読み込みされると、現在のシステムプロンプトが復元され、スキルやフックのコンテキストなど、関連する注入されたシステムメッセージのみが保持されます。

## 8. コンテキストオーバーフローの回復

プロバイダーからコンテキストウィンドウの範囲を超えたと報告された場合、uagは最近の履歴メッセージのうち容量の大きいものを特定し、そのメッセージとそれに続く履歴をロールバックしてから再試行します。これはリアクティブなフォールバックであり、通常の割り当て管理の代替ではありません。

## 9. プロバイダ側の継続と圧縮

サポートされている場合、Responses API は `previous_response_id` を使用して、クライアントからプロバイダが管理するレスポンス履歴全体を再送信することなく、レスポンスチェーンを継続します。

Responses API フローは、同じローカル縮小閾値を使用して、プロバイダー側の圧縮設定も送信します。具体的な動作はプロバイダーに依存しますが、ローカルの Artifact および履歴ポリシーは、プロバイダーに依存しない安全策として機能します。

## 10. トークンカウントの効率化

圧縮の判断に使用されるトークン数はキャッシュされ、新しいメッセージが追加された場合にのみ増分的に更新されます。 これによりモデルコンテキストが直接縮小されるわけではありませんが、圧縮が必要かどうかを判断する際のCPUコストとレイテンシが低減されます。

## まだ完全な統一レイヤーとはなっていない点

現在の実装では、以下のすべてを単一のプロバイダー中立なマネージャーとして提供できていません：

- 統一された `ContextManager` および `ContextBudget`；
- 重要度およびエヴィクションのメタデータを持つ `ToolResultRecord`；
- `LLM` を必要としないセマンティック要約;
- 関連するアーティファクトの自動取得および再注入；
- バイナリを生成するすべてのツールに対して`Artifact`変換を保証する中央の「結果マネージャー」；または
- システム、履歴、ツールスキーマ、結果のすべてのカテゴリにわたる優先順位を考慮したエヴィクション。

要するに、uagは現在、決定論的な切り捨て、Artifact参照、バイナリの隔離、動的なツール選択、履歴要約、プロバイダーの継続、およびオーバーフロー回復を組み合わせています。 統一されたコンテキスト層の設計ロードマップは、[UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md)に記載されている。
