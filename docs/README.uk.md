## Чому uag?

**Позбавтеся від блокування від постачальника.** Більшість помічників ШІ прив’язують вас до певного постачальника або хмарної служби. uag відрізняється.

- **Запускається локально** на вашій машині. Ваші дані залишаються з вами (за винятком API викликів, які ви здійснюєте).
- **Свобода постачальників**: OpenAI, Claude, Gemini, DeepSeek, Ollama, Azure, Bedrock, Novita, HuggingFace... 24 постачальники, усі доступні з одного інтерфейсу. Перемикайтеся між ними шляхом переналаштування змінних середовища — без перевстановлення, без міграції.
- **222 інструменти**: файловий ввід-вивід, веб-пошук, створення зображень, Gmail, сканування пристроїв BLE, інтеграція сервера MCP — **130 статично позначено як паралельно безпечні** (до 8 виконуються одночасно через пул потоків, налаштовуються через `UAGENT_PARALLEL_WORKERS`). Коли LLM запускає кілька викликів інструментів одночасно, uag автоматично розпаралелює їх.
- **3 UI + A2A**: CLI, GUI, Web і протокол «Агент-агент». Той самий движок, будь-який інтерфейс.
- **IoT Ready**: SwitchBot, ECHONET Lite, Matter, UPnP — керуйте своїми домашніми пристроями за допомогою штучного інтелекту.
- **Навички агента**: встановлюйте навички, створені спільнотою, із торгової площадки. Розширюйте uag нескінченно.

uag — **ваш помічник ШІ на ваших умовах**. Не прив’язаний до постачальника, не прив’язаний до інтерфейсу, не прив’язаний до платформи.

## Використання комп’ютера

Використання комп’ютера є опціональним і підтримує як видиме середовище виконання Playwright браузера
, так і середовище виконання на робочому столі. Коли ввімкнено, обидва середовища виконання створюються та реєструються;

```bat
set UAGENT_COMPUTER_USE=1
```

Використовуйте `desktop`, щоб вибрати натомість середовище виконання робочого столу ОС. Ресурси виконання
закриваються разом під час звичайного виходу, `Ctrl-C` і завершення процесу. Установіть
`UAGENT_COMPUTER_HEADLESS=1` для CI або димових тестів на основі веб-переглядача.
Див.## Голос у реальному часі та AEC3

Режим голосу в реальному часі підтримує OpenAI Realtime, Azure OpenAI GPT Realtime, xAI Grok Voice API, Google Gemini Multimodal Live API і Amazon Bedrock Nova Sonic із повнодуплексним мікрофоном і динаміком I/O. Необхідний `pywebrtc-audio` сервер AEC3 встановлюється автоматично, а додатковий двонаправлений потоковий SDK Bedrock встановлюється автоматично, лише коли вибрано постачальника Bedrock:

set UAGENT_REALTIME_AUDIO_DEBUG=1

OpenAI Realtime підтримує обмежену безпеку інтеграцію виклику функцій. Поточний адаптер реального часу автоматично надає доступ лише для читання `get_current_time`. #### Ollama та llama.cpp

Ollama та llama.cpp є окремими постачальниками. Ollama використовує власний сервіс і керування моделлю, а `llama.cpp` підключається до `llama-server` OpenAI-сумісної кінцевої точки:

```bash
# Ollama
UAGENT_PROVIDER=ollama
UAGENT_OLLAMA_BASE_URL=http://localhost:11434/v1
UAGENT_OLLAMA_DEPNAME=llama3.1
# llama.cpp / llama-server
UAGENT_PROVIDER=llama_cpp
UAGENT_LLAMA_CPP_BASE_URL=http://localhost:8080/v1
UAGENT_LLAMA_CPP_DEPNAME=local-model
UAGENT_LLAMA_CPP_API_KEY=dummy
```

Постачальник llama.cpp використовує шлях, сумісний із завершеннями чату. Зберігайте `UAGENT_RESPONSES=0`, якщо не налаштовано сумісний проксі.

### ⚡ Паралельне виконання інструментів

Коли LLM запитує кілька інструментів одночасно, uag **автоматично розпаралелює** їх.
130 інструментів статично позначаються як `x_parallel_safe` і виконуються одночасно через `ThreadPoolExecutor` (8 потоків за замовчуванням; установіть `UAGENT_PARALLEL_WORKERS` для зміни).
**Приклад**: запит «Перевірте погоду в скандинавських столицях» → LLM запускає `search_web` × 5 країн → усі 5 пошуків виконуються паралельно → результати збираються в одній групі.
Поточна кількість: на основі модулів інструментів, які визначають `TOOL_SPEC` (наразі 222, включаючи 2 інструменти з підтримкою Rust у `src/uagent/tools_rust/`). `http_request` використовує чутливу до методу безпеку: виклики `GET`/`HEAD`/`OPTIONS` можуть виконуватися паралельно, тоді як методи запису залишаються послідовними.
Інструменти лише для читання (пошук файлів, обчислення хешу, перелік каталогів, переклад, запити до БД тощо) агресивно розпаралелюються.

### 🧩 Система плагінів (код Claude). Сумісний)

uagent реалізує **Claude систему плагінів, сумісну з кодом**. Плагіни об’єднують навички, агентів, сервери MCP, хуки тощо в самостійні каталоги за допомогою маніфесту `.claude-plugin/plugin.json`.
**Підтримувані компоненти**: навички, субагенти, сервери MCP, хуки (12 подій життєвого циклу), команди похилої риски, стилі виведення, userConfig, Залежності, канали, Marketplaces
**Команди CLI**:

```
:список плагінів # Список встановлених плагінів
:plugin install <source> [--scope] # Install (dir/zip/git/http)
:plugin install <name>@<marketplace> # Install from marketplace
:plugin remove <name> # Uninstall
:plugin enable/disable <name> # Toggle
:plugin marketplace add/remove/list # Manage marketplaces
:plugin init <name> # Scaffold new plugin
```

### 🤖 Автопілот (`:auto`)

uag може **автономно досягати мети в кількох LLM раундах**. Ідеально підходить для складних багатоетапних завдань, які потребують повторного вдосконалення.

- **Як це працює**: кожен раунд містить основний запит (Крок A), за яким іде рішення рецензента (Крок B), яке вирішує «ЗАВЕРШИТИ чи ПРОДОВЖИТИ?»
- **Той самий постачальник, той самий API**: судження рецензента використовує ідентичний кодовий шлях як основний запит — включаючи підтримку відповідей API.
- **Окремо. суддя LLM** (необов’язково): налаштуйте `UAGENT_AP_PROVIDER` на використання іншого постачальника/моделі для рецензента (наприклад, використовуйте дешевшу модель для оцінювання).
- **Вийти в будь-який час**: натисніть клавішу F11, щоб негайно зупинитися, навіть посередині відповіді. Або дозвольте рецензенту вирішити, коли буде досягнуто мети.
- **Настроюється**: `--max-rounds N`, щоб контролювати бюджет.
  Див. [README_AUTO.md](https://github.com/awaku7/agentcli/blob/main/docs/README_AUTO.md), щоб отримати повну документацію.

### 🧩 Пакетний стан Менеджер

uag може відстежувати перебіг тривалих багатофайлових завдань. Коли LLM обробляє десятки файлів, `batch_state` зберігає на диску список файлів, що очікують на розгляд, завершених і невдалих. Якщо сеанс завершується або раунд минув, наступний запуск поновлюється з того місця, де він був зупинений — нічого не втрачається.

### 🛡 Human-in-the-Loop

`human_ask` дозволяє LLM призупинити роботу та запитати ваше підтвердження перед виконанням руйнівних операцій (видалення файлів, перезапис, команди оболонки). Ви залишаєтесь під контролем.

### 🛑 Переривання (клавіша c / кнопка зупинки)

Зупиніть генерацію відповіді LLM у будь-який час і надішліть команду зупинки назад до LLM.
| Інтерфейс | Як перервати |
|---|---|
| **CLI** | Натисніть клавішу F12 під час потокової передачі LLM — поточна відповідь припиняється, і `"Зупинити"` надсилається як повідомлення користувача, тому LLM відповідає відповідно |
| **ВЕБ-Інтерфейс користувача** | Натисніть червону кнопку **■ Зупинити** (з’являється автоматично під час обробки LLM) |
| **Графічний інтерфейс робочого столу** | Натисніть червону кнопку **■** (з’являється автоматично під час обробки LLM) |
Переривання працює як «оперативна ін’єкція»: замість того, щоб просто переривати, воно повертає «Зупинити» назад до LLM як повідомлення користувача, дозволяючи йому витончено завершити або підтвердити переривання.
Натисніть клавішу F11, щоб вийти з режиму автопілота (див. [README_AUTO.md](https://github.com/awaku7/agentcli/blob/main/docs/README_AUTO.md)).

### 🕵️ Автоматизація веб-переглядача та веб-інспектор

Два додаткових інструменти на основі Playwright:

- **browser_playwright**: автоматизація реальних сеансів браузера — навігація, клацання, заповнення форм, вилучення даних, керування багатосторінковими потоками. Працює як без голови, так і без голови.
- **playwright_inspector**: Записуйте переходи в браузері, створюйте знімки DOM і знімки екрана на кожному кроці. Корисно для налагодження веб-взаємодій або перевірки змін сторінки з часом.

### 🔄 Динамічне завантаження інструментів

`tool_catalog` і `tool_load` дозволяють знаходити та вмикати інструменти під час виконання.
Не потрібно завантажувати все під час запуску — активуйте лише те, що вам потрібно, коли вам це потрібно.

### 🦀 Власні інструменти Rust

`uuid_gen` і `slugify` реалізовано в Rust (через PyO3) для забезпечення продуктивності.
Вони завантажуються безпосередньо з попередньо зібраного `.pyd` — **не вимагається `pip-інсталяція`**.
Зовнішні розробники також можуть надавати інструменти на основі Rust: розмістіть `.pyd` поруч із
обгорткою `.py`, використовуйте `load_rust_pyd()` з `uagent.tools.rust_helper`, і
користувачі отримують інструмент без будь-яких додаткових залежностей. Див.
[TOOL_CREATOR_GUIDE.md](https://github.com/awaku7/agentcli/blob/main/TOOL_CREATOR_GUIDE.md).

### 🌐 i18n / L10n

日本語 / англійська / 简体中文 /繁體中文 / 한국어 / Español / Français / Русский / тощо.
Установіть `UAGENT_LANG` для перемикання. Перегляньте [ADD_LOCALE.md](https://github.com/awaku7/agentcli/blob/main/src/uagent/docs/ADD_LOCALE.md), щоб додати нову мову.
Переклади цього README доступні в [docs/README.translations.md](https://github.com/awaku7/agentcli/blob/main/docs/README.translations.md).

### Перевірки розробки (до PR)

Спочатку встановіть лише тестові залежності. Вони не потрапляють у список
залежностей середовища виконання:

```bash
python -m pip install -e "[test]"
python -m pip install black ruff
```

Виконайте ті самі перевірки, що використовуються GitHub Дії перед натисканням:

```bash
python -m ruff check src tests
python -m black --check src tests
python scripts/tool_json_i18n_batch.py status
python -m pytest -q .
```

Для швидшої локальної ітерації запустіть лише відповідні тести:

```bash
pytest -q tests/<affected_area>
```

Додаткові перевірки за необхідності:

```bash
python -m py_compile src/uagent/
mypy src/uagent
```

Після редагування локалі (`.po`): `python scripts/compile_locales.py` і `python scripts/po_qc_summary.py`.

Політика виконання (подробиці в [DEVELOP.md](https://github.com/awaku7/agentcli/blob/main/src/uagent/docs/DEVELOP.md) §6.1): помічники піднімають замість `sys.exit`; хост інструмента перетворює інструмент `SystemExit`/`Exception` на рядки помилок, тому один інструмент не може вбити процес. Швидкі виходи під час запуску залишаються навмисними.
