# Контекст шахалт ба хязгаарлагдмал загварын контекст

uag нь идэвхтэй загварын контекстыг хязгаарлагдмал байлгахын тулд хэд хэдэн давхаргыг ашигладаг. Зорилго нь хэрэглэгчид шаардлагатай байж болох файлууд, хэрэгслийн үр дүн эсвэл сессийн өгөгдлийг устгахгүйгээр шаардлагагүй оролтын тэмдэгтүүдийг бууруулах явдал юм.

Энэхүү баримт бичиг нь одоогийн хэрэгжилтийг тайлбарлана. Мөн энэ нь детерминистик зан үйл болон нийлүүлэгч-тусгай эсвэл LLM-ээр дэмжигдсэн зан үйл хоорондын ялгааг тодорхойлдог.

## 1. Динамик хэрэгслийн гадаргуу

Бүх хэрэгслийн тодорхойлолтыг эргэлт бүрт загвар руу илгээх шаардлагагүй.

- `tool_catalog` боломжит чадваруудыг хайдаг.
- `tool_load` одоогийн даалгаварт шаардлагатай хэрэгслүүдийг л идэвхжүүлдэг.
- `tool_catalog`, `tool_load`, болон `unload_tool` удирдлагын хэрэгслүүд хэвээр ашиглах боломжтой.
- GPT-5.4-тэй нийцтэй Responses API урсгалууд нь серверийн талын төрөлх Tool Search-ийг ашиглаж болно.
- Хуучин Tool Search горим нь клиент талд `tool_catalog` ашиглан хэрэгслийн тодорхойлолтыг багасгана.

Энэ нь хэрэгслийн схемийн оролтын тэмдэгтүүдийг, ялангуяа олон хэрэгсэл суулгасан тохиолдолд, бууруулдаг.

## 2. Том хэмжээний текстэн tool үр дүн Artifacts болдог

Хэрэв текстэн tool үр дүн Artifact хязгаарыг давсан бол, uag бүх үр дүнг Artifact хэлбэрээр хадгалан, бүтэн текст илгээхийн оронд загвар руу хязгаарлагдсан лавлагаа болон урьдчилсан хараг илгээдэг.

Анхдагч хязгаарлалтууд нь:

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

Моделд харагдах төлөөлөлд хэрэгслийн нэр, анхны урт, `artifact://` лавлагаа, хадгалах зам болон хязгаарлагдмал урьдчилсан харалт орно. Бүтэн үр дүн нь Artifact хадгалах сангаар дамжуулан хэвээр ашиглах боломжтой. Хязгаарыг `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS`–ээр өөрчилж болно. `0` утга нь Artifact дэмжлэгийг идэвхгүй болгодог. `UAGENT_TOOL_RESULT_MAX_CHARS` нь ердийн хязгаарлагдмал үр дүнгийн бодлогыг удирддаг; `0` нь тэр хязгаарыг идэвхгүй болгодог.

## 3. Хязгаарлагдмал Artifact татан авалт

`artifact_read` дэд бүтцийн хэрэгсэл нь Artifact-ээс зөвхөн хүссэн хэсгийг татан авдаг:

- `start_line` эхний мөрнийг сонгодог.
- `max_lines` нь 500-д хязгаарлагддаг.
- `max_chars` нь 50,000 тэмдэгтэд хязгаарлагддаг.
- Artifact ID болон `artifact://` URI хоёуланг ашиглаж болно.

Энэ нь бүх файлыг эсвэл командын үр дүнг дахин оруулахын оронд жижиг, холбогдох хэсгийг шалгах боломжийг олгодог.

Шинэ Artifacts доор хадгалагдсан байна:

```text
~/.uag/artifacts/
```

Одоогийн хуучин Artifact замууд нийцтэй байдлыг хангах үүднээс уншигддаг хэвээр байна.

## 4. Хоёртын ачааг тусгаарлах

Мөрөнд оруулсан хоёртын өгөгдлийг дараагийн загварын эргэлтэд текст хэлбэрийн хэрэгслийн үр дүнд илгээхгүй. Base64 хэлбэрийн талбаруудыг дараах богино тэмдэглэгээгээр солино:

```text
[LLM контекстоос binary payload хасагдсан]
```

Хэрэглэгчийн интерфейс болон алсын клиентүүд санах ойд хадгалагдсан хавсралтуудыг хүлээн авч, хадгалагдсан файлууд нь тэдгээрийн замууд эсвэл Artifact лавлагаагаар дамжуулан ашиглах боломжтой хэвээр байна. Энэ нь зураг, аудио, дэлгэцийн агшин зургууд болон бусад хоёртын ачаалгыг текст загварын контекстийг томруулахыг зогсооно.

Адил төрлийн хоёртын ачаалгыг SQLite болон JSONL хадгалалтаас өмнө цэвэрлэдэг тул сесс дахин ачаалагдсаны дараа том хэмжээний ачаалга болж буцаж ирэхээс сэргийлнэ.

## 5. Автомат түүхийн шахалт

uag нь мессежийн тоо эсвэл тооцсон токен тоо тохируулсан хязгаарт хүрэхэд хуучин ярианы түүхийг шахаж болно.

Шахлагын бодлого нь дараахыг ашиглана:

- системийн бус мессежийн тоо;
- боломжтой үед загварын шийдэгдсэн контекстийн цонх;
- `UAGENT_SHRINK_KEEP_LAST` (анхдагчаар 20);
- `UAGENT_SHRINK_MAX_TOKENS` эсвэл загварын тусгай хязгаарлалт;
- `UAGENT_SHRINK_CNT`; болон
- `UAGENT_SHRINK_RATIO` (контекст цонх тодорхой үед анхдагчаар 0.5).

Загвар тусгай хязгаарыг дараах байдлаар өгч болно:

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

Өмнөх хураангуйг эргэлт бүрт дахин үүсгэхгүй. Хистерез нь шахалт дахин явагдахаас өмнө хангалттай шинэ түүх хуримтлагдах эсвэл токен-төсвийн давчидлыг шаарддаг.

## 6. LLM-ээр тусласан түүхийн хураангуй

Автомат шахалт LLM-ийг ашиглах үед хуучин хэрэглэгчийн, туслах болон хэрэгслийн мессежүүдийг эргэлтэт систем мессеж болгон хураангуйлан бичигддэг ба сүүлийн хэсгийг хадгалдаг.

Урт түүхүүдийг хэсэгчлэн хураангуйлах боломжтой. Холбогдох удирдлагууд нь:

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

Товчлолыг хязгааргүй олон товчлолын мессежийн дараалал үүсгэхийн оронд урд зүгт эвхдэг. Энэ нь LLM-ээр туслалцсан үйлдэл бөгөөд нэмэлт үйлчилгээ үзүүлэгчийн хүсэлт шаардлагатай байж болно.

## 7. Тодорхой (deterministic) нөөц шахалт

Хэрэв LLM хураангуй бэлэн биш бол, uag нь системийн эхний мессежүүдийг болон зөвхөн хамгийн сүүлийн мессежүүдийг хадгална. Тохируулгын дуудлагын хил хязгаарыг засварлан, үүсэх түүх ганцаардсан тохируулгын дуудлагаар эхлэх эсвэл дуусахгүй байхыг хангана.

Loader ба sanitizer нь загварт хамааралгүй эсвэл хүчин төгөлдөр бус бичлэгүүдийг, үүнд зөвхөн UI-д зориулсан мессежүүд, дотоод удирдлагын мессежүүд, эвдэрсэн лог мөрүүд, дэмжлэггүй үүрэгүүд, ганцаардсан тохируулгын үр дүн болон дутуу тохируулгын дуудлагын блокуудыг устгана.

Сесс дахин ачаалагдах үед одоогийн системийн уриалгыг сэргээж, зөвхөн холбогдох тарьсан системийн мессежүүд, жишээлбэл чадвар эсвэл хук контекст, хадгалагдана.

## 8. Контекстын хэтрэх байдлыг сэргээх

Хэрэв үйлчилгээ үзүүлэгч контекстын цонх хэтэрсэн гэж мэдээлвэл, uag сүүлийн үеийн том түүхийн мессежийг илрүүлж, түүнийг болон дараах түүхийн бичлэгийг буцааж, дахин оролдохын өмнө сэргээдэг. Энэ нь ердийн төсөвлөлтийг орлохгүй, харин реактив нөөцлөлт юм.

## 9. Үйлчилгээ үзүүлэгчийн талын үргэлжлэл ба шахмалжуулалт

Дэмжигдсэн тохиолдолд Responses API нь `previous_response_id` ашиглан үйлчлүүлэгч рүү бүх үйлчилгээ үзүүлэгчийн удирддаг хариу түүхийг дахин илгээхгүйгээр хариуны гинжийг үргэлжлүүлдэг.

Responses API урсгалууд мөн ижил орон нутгийн шахмал хязгаарыг ашиглан үйлчилгээ үзүүлэгчийн талын шахмал тохиргоог илгээдэг. Яг ямар үйлдэл хийх нь үйлчилгээ үзүүлэгчээс хамаарна; орон нутгийн Artifact болон түүхийн бодлого нь үйлчилгээ үзүүлэгчээс үл хамаарах хамгаалалтын механизм хэвээр үлдэнэ.

## 10. Тэмдэгтийн тоог тоолох үр ашиг

Шахалтын шийдвэр гаргахад ашиглагддаг тэмдэгтийн тоог компресс хийж, зөвхөн шинэ мессежүүд нэмэгдсэн үед шат дараатай шинэчилдэг. Энэ нь шууд загварын контекстыг бууруулдаггүй, харин шахалт хэзээ шаардлагатайг шийдэхэд шаардагдах CPU зардал, сааталтыг бууруулдаг.

## Одоогоор бүрэн нэгтгэгдээгүй давхарга

Одоогийн хэрэгжилт дараах бүхнийг нэг ханган нийлүүлэгч-хараат бус менежерээр бүрэн хангахгүй байна:

- нэгтгэсэн `ContextManager` ба `ContextBudget`;
- ач холбогдол болон хаялтын мета өгөгдөл бүхий `ToolResultRecord`;
- LLM шаарддаггүй семантик хураангуй;
- холбогдох Artifacts-ыг автоматаар татаж, дахин шахах;
- бүх бинар гаргадаг хэрэгслийн Artifact хөрвүүлэлтийг баталгаажуулдаг төв Result Manager; эсвэл
- систем, түүх, tool-schema болон үр дүнгийн бүх ангилалд давуу эрхийн дагуу хасалт хийх.

Товчхондоо, uag нь одоогоор тодорхойлогдсон таслалт, Artifact лавлагаа, хоёртын тусгаарлалт, динамик хэрэгслийн сонголт, түүхийн хураангуй, үйлчилгээ үзүүлэгчийн үргэлжлэл болон хэт ачааллын сэргээх үйлдлийг нэгтгэн ажиллаж байна. Нэгтгэсэн контекст давхаргын загварын замын зураг нь [UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md)-д баримтжуулсан.
