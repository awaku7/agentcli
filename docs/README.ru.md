## Почему uag?

**Освободитесь от привязки к поставщику.** Большинство ИИ-помощников привязывают вас к конкретному поставщику или облачному сервису. uag отличается.

- **Запускается локально** на вашем компьютере. Ваши данные остаются с вами (за исключением звонков API).
- **Свобода провайдера**: OpenAI, Claude, Gemini, DeepSeek, Ollama, Azure, Bedrock, Novita, HuggingFace... 24 провайдера, все доступны из единого интерфейса. Переключайтесь между ними путем перенастройки переменных среды — без переустановки, без миграции.
- **222 инструмента**: файловый ввод-вывод, веб-поиск, генерация изображений, Gmail, сканирование устройств BLE, интеграция с сервером MCP — **130 статически помечены как параллельные безопасные** (до 8 выполняются одновременно через пул потоков, настраивается через `UAGENT_PARALLEL_WORKERS`). Когда LLM одновременно запускает несколько вызовов инструментов, uag автоматически распараллеливает их.
- **3 интерфейса пользователя + A2A**: интерфейс командной строки, графический интерфейс пользователя, веб-интерфейс и протокол агент-агент. Тот же механизм, любой интерфейс.
- **Поддержка Интернета вещей**: SwitchBot, ECHONET Lite, Matter, UPnP — управляйте своими домашними устройствами с помощью искусственного интеллекта.
- **Навыки агента**: установите навыки, созданные сообществом, с торговой площадки. Расширяйте uag бесконечно.

uag — **ваш искусственный помощник на ваших условиях**. Не привязан к провайдеру, не привязан к интерфейсу, не привязан к платформе.

## Использование компьютера

Использование компьютера является добровольным и поддерживает как видимую среду выполнения браузера Playwright
, так и среду выполнения рабочего стола. Если этот параметр включен, обе среды выполнения создаются и регистрируются;

```bat
set UAGENT_COMPUTER_USE=1
```

Вместо этого используйте `desktop`, чтобы выбрать среду выполнения рабочего стола ОС. Ресурсы среды выполнения закрываются вместе при обычном выходе, нажатии Ctrl-C и завершении процесса. Установите
`UAGENT_COMPUTER_HEADLESS=1` для CI или дымовых тестов на основе браузера.
Подробности об интеграции и безопасности см. в [docs/COMPUTER_USE_IMPLEMENTATION.md](docs/COMPUTER_USE_IMPLEMENTATION.md)
.

## Realtime Voice и AEC3

Голосовой режим в реальном времени поддерживает OpenAI Realtime, Azure OpenAI GPT Realtime, xAI Grok Voice API, Google Gemini Multimodal Live API и Amazon Bedrock Nova Sonic с полнодуплексным микрофоном и динамиком ввода-вывода. Требуемый серверный компонент AEC3 `pywebrtc-audio` устанавливается автоматически, а дополнительный SDK двунаправленной потоковой передачи Bedrock устанавливается автоматически только при выборе поставщика Bedrock:

```bash
python scheck.py realtime
```

Конвейер AEC3 получает фактический сигнал микрофона ("near") и звук, фактически передаваемый говорящему ("far"), чтобы помощник мог слушать во время разговора. Включайте диагностику только при обнаружении проблем со звуком:

```bat
set UAGENT_REALTIME_AUDIO_DEBUG=1
python scheck.py realtime
```

### OpenAI Вызов функций в реальном времени

OpenAI Realtime поддерживает интеграцию вызовов функций с ограничениями по безопасности. Текущий адаптер реального времени автоматически предоставляет `get_current_time` только для чтения. Деструктивные инструменты и элементы управления устройствами не доступны без явного списка разрешений и потока подтверждения. Grok Realtime использует отдельный адаптер и не использует этот путь вызова функций, специфичный для OpenAI.

Все поставщики используют один и тот же набор инструментов и интерфейс. Переключитесь, настроив UAGENT_PROVIDER — никаких изменений кода и отдельной установки.

#### Ollama и llama.cpp

Ollama и llama.cpp — отдельные поставщики. Ollama использует собственный сервис и управление моделями, а `llama.cpp` подключается к `llama-server` OpenAI-совместимой конечной точке:

```bash
# Ollama
UAGENT_PROVIDER=ollama
UAGENT_OLLAMA_BASE_URL=http://localhost:11434/v1
UAGENT_OLLAMA_DEPNAME=llama3.1
# llama.cpp / llama-server
UAGENT_PROVIDER=llama_cpp
UAGENT_LLAMA_CPP_BASE_URL=http://localhost:8080/v1
UAGENT_LLAMA_CPP_DEPNAME=local-model
UAGENT_LLAMA_CPP_API_KEY=dummy
```

Провайдер llama.cpp использует Путь, совместимый с Chat Completions. Сохраняйте `UAGENT_RESPONSES=0`, если не настроен совместимый прокси.

### ⚡ Параллельное выполнение инструментов

Когда LLM запрашивает несколько инструментов одновременно, uag **автоматически распараллеливает** их.
130 инструментов статически помечаются `x_parallel_safe` и выполняются одновременно через `ThreadPoolExecutor` (по умолчанию 8 потоков; установлено `UAGENT_PARALLEL_WORKERS`, чтобы изменить).
**Пример**: Спросите "Проверьте погоду в столицах Северных стран" → LLM запускает `search_web` × 5 стран → все 5 поисковых запросов выполняются параллельно → результаты собраны в один пакет.
Текущее количество основано на модулях инструментов, которые определяют `TOOL_SPEC` (на данный момент 222, включая 2 инструмента на базе Rust в `src/uagent/tools_rust/`). `http_request` использует безопасность, чувствительную к методу: вызовы `GET`/`HEAD`/`OPTIONS` могут выполняться параллельно, в то время как методы записи остаются последовательными.
Инструменты только для чтения (поиск файлов, вычисление хэша, список каталогов, перевод, запросы к базе данных и т. д.) активно распараллеливаются.

### 🧩 Система плагинов (совместимость с кодом Claude)

uagent реализует **Claude Совместимая с кодом система плагинов**. Плагины объединяют навыки, агенты, серверы MCP, перехватчики и многое другое в автономные каталоги с манифестом `.claude-plugin/plugin.json`.
**Поддерживаемые компоненты**: навыки, субагенты, серверы MCP, перехватчики (12 событий жизненного цикла), команды Slash, стили вывода, userConfig, зависимости, каналы, торговые площадки
**CLI команды**:

```
:plugin list # Список установленных плагинов
:plugin install <source> [--scope] # Install (dir/zip/git/http)
:plugin install <name>@<marketplace> # Установить из магазина
:plugin удалить <имя> # Uninstall
:plugin include/disable <name> # Toggle
:plugin marketplace add/remove/list # Manage marketplaces
:plugin init <name> # Scaffold new plug
```

Полную документацию см. в [DEVELOP_PLUGIN.md](src/uagent/docs/DEVELOP_PLUGIN.md).

### 🔄 Непрерывность сеанса

- **Смена провайдера в середине сеанса** с помощью `UAGENT_PROVIDER` — история разговора сохраняется.
- **Перезагрузите прошлые сеансы** с помощью `:load <index>` — продолжайте с того места, где вы остановились.
- **Кэширование результатов инструмента** позволяет избежать избыточного повторного выполнения при повторении одного и того же вызова инструмента.

### 🤖 Автопилот (`:auto`)

uag может **автономно достигать цели в течение нескольких LLM раундов**. Идеально подходит для сложных, многоэтапных задач, требующих итеративной доработки.

- **Как это работает**: каждый раунд состоит из основного запроса (шаг A), за которым следует решение рецензента (шаг B), которое принимает решение «ЗАВЕРШИТЬ или ПРОДОЛЖИТЬ?»
- **Тот же поставщик, тот же API**: В решении рецензента используется тот же путь кода, что и в основном запросе, включая поддержку ответов API.
- **Отдельный судья LLM** (необязательно): установить `UAGENT_AP_PROVIDER`, чтобы использовать другого поставщика/модель для рецензента (например, использовать более дешевую модель для оценки).
- **Выйти в любое время**: нажмите клавишу F11, чтобы немедленно остановиться, даже в середине ответа. Или позвольте рецензенту решить, когда цель будет достигнута.
- **Настраивается**: `--max-rounds N` для контроля бюджета.
  Полную документацию см. в [README_AUTO.md](https://github.com/awaku7/agentcli/blob/main/docs/README_AUTO.md).

### 🧩 Batch State Manager

uag может отслеживать ход выполнения длительных многофайловых задач. Когда LLM обрабатывает десятки файлов, `batch_state` сохраняет на диске список ожидающих, завершенных и неудавшихся файлов. Если сеанс заканчивается или истекает время раунда, следующий запуск возобновляется с того места, где он был остановлен — ничего не теряется.

### 🛡 Human-in-the-Loop

`human_ask` позволяет LLM приостановить работу и запросить ваше подтверждение перед выполнением разрушительных операций (удаление файла, перезапись, команды оболочки). Вы сохраняете контроль.

### 🛑 Прерывание (клавиша c/кнопка «Стоп»)

Остановите генерацию ответа LLM в любой момент и введите команду остановки обратно в LLM.
| Интерфейс | Как прервать |
|---|---|
| **CLI** | Нажмите клавишу F12 во время потоковой передачи LLM — текущий ответ останавливается, и `"Stop"` отправляется как пользовательское сообщение, поэтому LLM отвечает соответствующим образом |
| **ВЕБ-интерфейс** | Нажмите красную кнопку **■ Стоп** (появляется автоматически во время обработки LLM) |
| **Графический интерфейс рабочего стола** | Нажмите красную кнопку \*\*\*\*\*\* (появляется автоматически во время обработки LLM) |
Прерывание работает как «подсказка»: вместо простого прерывания оно передает «Стоп» обратно на LLM в качестве пользовательского сообщения, позволяя ему корректно завершить или подтвердить прерывание.
Нажмите клавишу F11, чтобы выйти из режима автопилота (см. [README_AUTO.md](https://github.com/awaku7/agentcli/blob/main/docs/README_AUTO.md)).

### 🕵️ Автоматизация браузера и веб-инспектор

Два взаимодополняющих инструмента на основе Playwright:

- **browser_playwright**: автоматизация реальных сеансов браузера — навигация, нажатие, заполнение форм, извлечение данных, обработка многостраничные потоки. Работает без головы или с головой.
- **playwright_inspector**: записывайте переходы в браузере, делайте снимки DOM и снимки экрана на каждом этапе. Полезно для отладки веб-взаимодействий или аудита изменений страниц с течением времени.

### 🔄 Динамическая загрузка инструментов

`tool_catalog` и `tool_load` позволяют обнаруживать и включать инструменты во время выполнения.
Нет необходимости загружать все при запуске — активируйте только то, что вам нужно, и тогда, когда вам это нужно.

### 🦀 Встроенные инструменты Rust

`uuid_gen` и `slugify` реализованы в Rust (через PyO3) для повышения производительности.
Они загружаются напрямую из предварительно созданного `.pyd` — \*\*установка pip`не требуется**. Внешние разработчики также могут поставлять инструменты на основе Rust: поместите`.pyd`рядом с оболочкой`.py`, используйте `load_rust_pyd()`из`uagent.tools.rust_helper\`, и
пользователи получат инструмент без каких-либо дополнительных зависимостей. См.

## Философия проекта

uag стремится быть **вашим искусственным интеллектом, на вашей машине, на ваших условиях.**

- Нет зависимости от SaaS — работает локально
- Нет привязки к поставщику — переключайтесь в любое время
- Нет привязки к пользовательскому интерфейсу — CLI/GUI/Web / A2A
- Нет привязки к функциям — расширяйте возможности с помощью инструментов и навыков

Бесплатный агент AI, не требует привязки к поставщику.

### ✨ Создайте свои собственные инструменты

Написать новый инструмент для uag очень просто — создайте один файл `.py` с помощью
`TOOL_SPEC` и `run_tool()`, поместите его в `UAGENT_EXTERNAL_TOOLS_DIR`, и
он сразу же станет доступен. Разработчикам Rust предоставьте готовый файл `.pyd` с
нулевыми дополнительными зависимостями для пользователей.

Пошаговое руководство см. в [TOOL_CREATOR_GUIDE.md](https://github.com/awaku7/agentcli/blob/main/TOOL_CREATOR_GUIDE.md)
.

### Проверки разработки (перед PR)

Установите сначала тестовые зависимости. Они исключены из списка зависимостей среды выполнения:

```bash
python -m pip install -e ".[test]"
python -m pip install black ruff
```

Выполните те же проверки, что и GitHub Действия перед отправкой:

```bash
python -m ruff check src tests
python -m black --check srctests
python scripts/tool_json_i18n_batch.py status
python -m pytest -q .
```

Для более быстрой локальной итерации запускайте только затронутые тесты:

```bash
pytest -q tests/<affected_area>
```

Дополнительные проверки, если необходимо:

```bash
python -m py_compile src/uagent/
mypy src/uagent
```

После редактирования локали (`.po`): `python scripts/compile_locales.py` и `python scripts/po_qc_summary.py`.

Политика выполнения (подробности в [DEVELOP.md](https://github.com/awaku7/agentcli/blob/main/src/uagent/docs/DEVELOP.md) §6.1): помощники поднимают вместо `sys.exit`; хост инструмента преобразует инструмент SystemExit/Exception в строки ошибок, поэтому один инструмент не может завершить процесс. Быстродействующие выходы при запуске остаются преднамеренными.
