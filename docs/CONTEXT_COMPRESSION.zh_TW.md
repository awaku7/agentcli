# 上下文壓縮與有限模型上下文

uag 透過多層架構來確保活躍的模型上下文保持在有限範圍內。 其目標是在不移除使用者可能仍需要的檔案、工具結果或工作階段資料的前提下，減少不必要的輸入標記。

本文檔描述了當前的實作方式，並區分確定性行為與供應商特定行為或由 LLM 輔助的行為。

## 1. 動態工具介面

並非每個回合都需要將所有工具定義傳送至模型。

- `tool_catalog` 會搜尋可用的功能。
- `tool_load` 僅啟用當前任務所需的工具。
- `tool_catalog`、`tool_load` 及 `unload_tool` 仍作為管理工具提供。
- 與 GPT-5.4 相容的 Responses API 流程可使用原生伺服器端的 Tool Search。
- 傳統的 Tool Search 模式會透過客戶端側的 `tool_catalog` 縮小工具規格範圍。

這可減少工具模式所使用的輸入標記數量，特別是在安裝了大量工具的環境中。

## 2. 大型文字型工具結果將轉為「工件」

當文字型工具結果超過 Artifact 閾值時，uag 會將完整結果儲存為 Artifact，並向模型傳送有限範圍的參考與預覽，而非全文。

預設限制如下：

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

模型可見的表示形式包含工具名稱、原始長度、一個 `artifact://` 參考、儲存路徑以及受限預覽。 完整的結果仍可透過 Artifact 儲存庫取得。

閾值可透過 `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS` 進行調整。若設定為 `0`，則會停用 Artifact 提升功能。`UAGENT_TOOL_RESULT_MAX_CHARS` 用於控制一般的有界結果政策；若設定為 `0`，則會停用該一般限制。

## 3. 有限範圍的 Artifact 擷取

`artifact_read` 基礎架構工具僅擷取 Artifact 中被請求的部分：

- `start_line` 選取第一行。
- `max_lines` 上限定為 500。
- `max_chars` 上限定為 50,000 個字元。
- 既可使用 Artifact ID，也可使用 `artifact://` URI。

這使得我們能夠檢視一小段相關範圍，而非將整個檔案或指令結果重新注入下一個模型輪次。

新的產出結果儲存於以下位置：

```text
~/.uag/artifacts/
```

為維持相容性，現有的舊版 Artifact 路徑仍可讀取。

## 4. 二進位有效載荷隔離

內嵌的二進位資料不會作為文字形式的工具結果傳送至下一個模型輪次。 Base64 格式的欄位將被替換為簡短標記，例如：

```text
[從 LLM 上下文中省略的二進位有效載荷]
```

使用者介面與遠端客戶端仍可接收記憶體內的附件，且儲存的檔案仍可透過其路徑或 Artifact 參照存取。 此舉可防止圖片、音訊、螢幕截圖及其他二進位載荷導致文字型模型上下文過度膨脹。

同類型的二進位載荷在進行 SQLite 和 JSONL 持久化儲存前會先經過淨化處理，以防止其在會話重新載入後以大型載荷形式回傳。

## 5. 自動歷史紀錄壓縮

當訊息數量或預估標記數量達到設定的上限時，uag 可壓縮較舊的對話歷史紀錄。

壓縮政策會參考以下因素：

- 非系統訊息的數量；
- 若可用，則採用模型已解析的上下文視窗；
- `UAGENT_SHRINK_KEEP_LAST`（預設為 20）；
- `UAGENT_SHRINK_MAX_TOKENS` 或特定模型的覆寫設定；
- `UAGENT_SHRINK_CNT`；以及
- `UAGENT_SHRINK_RATIO`（當已知上下文視窗時，預設為 0.5）。

可透過以下方式指定模型專屬的限制：

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

系統不會在每個回合都重新生成先前已生成的摘要。 遲滯機制要求必須累積足夠的新歷史記錄，或發生另一次標記預算溢出，壓縮才會再次執行。

## 6. 由 LLM 輔助的歷史記錄摘要

當自動壓縮使用 LLM 時，較舊的使用者、助理及工具訊息會被摘要為滾動式系統訊息，同時保留最近的尾部內容。

長歷史記錄可分段進行摘要。 相關控制參數如下：

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

摘要會向前折疊，而非產生無界數量的摘要訊息序列。 這是一項由 LLM 輔助的操作，可能需要額外的提供者請求。

## 7. 確定性備用壓縮

若 LLM 摘要不可用，uag 可保留前導系統訊息以及僅保留最新訊息。 工具呼叫邊界會被修復，以確保最終的歷史紀錄不會以孤立的工具呼叫開頭或結尾。

載入器與清理器還會移除與模型無關或無效的條目，包括僅限 UI 的訊息、內部控制訊息、損壞的日誌行、不支援的角色、孤立的工具結果，以及不完整的工具呼叫區塊。

當重新載入工作階段時，會還原當前的系統提示，並僅保留相關的注入式系統訊息（例如技能或掛鉤上下文）。

## 8. 上下文溢出恢復

若提供者回報上下文視窗已超出，uag 會識別出一則較大的近期歷史記錄訊息，並在重試前回滾該訊息及其後續的歷史記錄。這是一種反應式備用機制，並非用於取代正常的資源預算管理。

## 9. 提供者端的延續與壓縮

在受支援的情況下，Responses API 會使用 `previous_response_id` 來延續回應鏈，而無需從客戶端重新傳送整個由提供者管理的回應歷史紀錄。

Responses API 流程亦會使用相同的本地壓縮閾值，傳送供應商端的壓縮配置。確切的行為取決於供應商；本地 Artifact 及歷史記錄政策仍為供應商中立的防護措施。

## 10. 標記計數效率

用於壓縮決策的標記計數會被快取，並僅在新增訊息時以增量方式更新。 這雖不會直接減少模型上下文，但能降低判斷何時需要壓縮所產生的 CPU 開銷與延遲。

## 尚未完全統一的層級

目前的實作尚未將以下所有功能整合為單一的供應商中立管理器：

- 統一的 `ContextManager` 與 `ContextBudget`；
- 具備重要度與淘汰元資料的 `ToolResultRecord`；
- 無需依賴 `LLM` 的語義摘要；
- 相關工件的自動檢索與重新注入；
- 一個中央結果管理器，確保每個產生二進位檔的工具皆能進行 `Artifact` 轉換；或
- 橫跨所有系統、歷史、工具模式及結果類別的優先級感知驅逐機制。

簡而言之，uag 目前結合了確定性截斷、Artifact 參照、二進位檔隔離、動態工具選取、歷史摘要、提供者延續以及溢出恢復等功能。 統一上下文層的設計路線圖詳見 [UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md)。
