# Сжатие контекста и ограниченный контекст модели

uag использует несколько уровней для обеспечения ограниченности активного контекста модели. Цель состоит в том, чтобы сократить количество ненужных входных токенов, не удаляя при этом файлы, результаты работы инструментов или данные сеанса, которые могут по-прежнему понадобиться пользователю.

В данном документе описывается текущая реализация. В нём также проводится различие между детерминированным поведением и поведением, зависящим от конкретного поставщика или поддерживаемым LLM.

## 1. Динамическая поверхность инструментов

Не каждое определение инструмента необходимо отправлять в модель в каждом ходу.

- `tool_catalog` выполняет поиск среди доступных возможностей.
- `tool_load` включает только те инструменты, которые необходимы для текущей задачи.
- `tool_catalog`, `tool_load` и `unload_tool` остаются доступными в качестве инструментов управления.
- Потоки Responses API, совместимые с GPT-5.4, могут использовать нативный серверный Tool Search.
- Устаревший режим Tool Search сужает спецификации инструментов с помощью `tool_catalog` на стороне клиента.

Это сокращает количество входных токенов, используемых схемами инструментов, особенно в установках с большим количеством инструментов.

## 2. Объёмные текстовые результаты инструментов становятся артефактами

Когда текстовый результат инструмента превышает пороговое значение Artifact, uag сохраняет полный результат в формате Artifact и отправляет модели ограниченную ссылку и предварительный просмотр вместо полного текста.

Ограничения по умолчанию:

```text
UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS=100000
UAGENT_TOOL_RESULT_MAX_CHARS=12000
```

Представление, доступное модели, содержит название инструмента, исходную длину, ссылку `artifact://`, путь к хранилищу и ограниченный фрагмент предварительного просмотра. Полный результат по-прежнему доступен через хранилище Artifact.

Пороговое значение можно изменить с помощью `UAGENT_TOOL_RESULT_ARTIFACT_THRESHOLD_CHARS`. Значение `0` отключает продвижение Artifact. `UAGENT_TOOL_RESULT_MAX_CHARS` управляет обычной политикой ограниченных результатов; `0` отключает этот обычный лимит.

## 3. Извлечение ограниченного Artifact

Инфраструктурный инструмент `artifact_read` извлекает только запрошенную часть Artifact:

- `start_line` выбирает первую строку.
- `max_lines` ограничено 500 строками.
- `max_chars` ограничено 50 000 символами.
- Можно использовать как идентификатор Artifact, так и URI `artifact://`.

Это позволяет анализировать небольшой релевантный диапазон вместо повторной подачи всего файла или результата команды в следующий цикл модели.

Новые артефакты хранятся ниже:

```text
~/.uag/artifacts/
```

Существующие устаревшие пути Artifact остаются доступными для чтения в целях совместимости.

## 4. Изоляция двоичных данных

Встроенные двоичные данные не отправляются в следующий цикл модели в виде текстового результата инструмента. Поля формата Base64 заменяются коротким маркером, например:

```text
[бинарные данные опущены из контекста LLM]
```

Пользовательский интерфейс и удалённые клиенты по-прежнему могут получать вложения, хранящиеся в памяти, а сохраненные файлы остаются доступными по их путям или ссылкам Artifact. Это предотвращает раздувание текстового контекста модели изображениями, аудио, скриншотами и другими бинарными данными.

Данные одного и того же типа очищаются перед сохранением в SQLite и JSONL, что предотвращает их возвращение в виде большого объёма данных после перезагрузки сеанса.

## 5. Автоматическое сжатие истории

uag может сжимать старую историю переписки, когда количество сообщений или расчетное количество токенов достигает настроенного предела.

Политика сжатия использует:

- количество несистемных сообщений;
- разрешенное контекстное окно модели, если оно доступно;
- `UAGENT_SHRINK_KEEP_LAST` (по умолчанию 20);
- `UAGENT_SHRINK_MAX_TOKENS` или переопределение, специфичное для модели;
- `UAGENT_SHRINK_CNT`; и
- `UAGENT_SHRINK_RATIO` (по умолчанию 0,5, если окно контекста известно).

Ограничение, специфичное для модели, можно указать следующим образом:

```text
UAGENT_SHRINK_MAX_TOKENS_<MODEL_NAME>
```

Предыдущее резюме не генерируется заново на каждом ходу. Для повторного запуска сжатия требуется накопление достаточного количества новых событий в истории или очередное превышение бюджета токенов.

## 6. Сводки истории с использованием LLM

Когда при автоматическом сжатии используется LLM, старые сообщения пользователей, помощников и инструментов сводятся в скользящее системное сообщение, при этом сохраняется недавняя конечная часть.

Длинные истории можно сводить частями. Соответствующие параметры:

```text
UAGENT_SHRINK_CHUNK_SIZE=100
UAGENT_SHRINK_SINGLE_SHOT=1
```

Сводка сдвигается вперёд, а не формирует неограниченную последовательность сводных сообщений. Эта операция выполняется с помощью LLM и может потребовать дополнительных запросов к провайдеру.

## 7. Детерминированное резервное сжатие

Если сводка LLM недоступна, uag может сохранять начальные системные сообщения и только самые последние сообщения. Границы вызовов инструментов восстанавливаются таким образом, чтобы итоговая история не начиналась и не заканчивалась «осиротевшим» вызовом инструмента.

Загрузчик и санитайзер также удаляют записи, не имеющие отношения к модели или являющиеся недействительными, включая сообщения, предназначенные исключительно для пользовательского интерфейса, внутренние управляющие сообщения, поврежденные строки журнала, неподдерживаемые роли, «осиротевшие» результаты инструментов и неполные блоки вызовов инструментов.

При перезагрузке сеанса восстанавливается текущий системный запрос, а сохраняются только релевантные вставленные системные сообщения, такие как контекст навыка или хука.

## 8. Восстановление после переполнения контекста

Если провайдер сообщает о превышении окна контекста, uag выявляет самое объёмное сообщение из недавней истории и откатывает это сообщение вместе со следующей за ним историей перед повторной попыткой. Это реактивный резервный механизм, а не замена обычного ограничения объёма.

## 9. Продолжение и уплотнение на стороне провайдера

Там, где это поддерживается, Responses API использует `previous_response_id` для продолжения цепочки ответов без повторной отправки с клиента всей истории ответов, управляемой провайдером.

Потоки Responses API также отправляют конфигурацию уплотнения на стороне провайдера, используя тот же локальный порог сжатия. Точное поведение зависит от провайдера; локальные Artifact и политики истории остаются независимыми от провайдера механизмами защиты.

## 10. Эффективность подсчёта токенов

Количество токенов, используемое для принятия решений о сжатии, кэшируется и обновляется инкрементально, когда добавляются только новые сообщения. Это не приводит к непосредственному сокращению контекста модели, но снижает затраты процессорного времени и задержку при принятии решения о необходимости сжатия.

## Что пока не является полным унифицированным уровнем

Текущая реализация пока не предоставляет все перечисленное ниже в виде единого менеджера, независимого от провайдера:

- унифицированные `ContextManager` и `ContextBudget`;
- `ToolResultRecord` с метаданными о важности и удалении;
- семантические сводки, не требующие использования `LLM`;
- автоматический поиск и повторная инъекция релевантных артефактов;
- центральный менеджер результатов, гарантирующий преобразование `Artifact` для каждого инструмента, генерирующего двоичные файлы; или
- вытеснение с учётом приоритетов во всех категориях: системной, истории, схемы инструмента и результатов.

Короче говоря, в настоящее время uag сочетает в себе детерминированное усечение, ссылки Artifact, изоляцию двоичных файлов, динамический выбор инструментов, сводки истории, продолжение работы поставщика и восстановление после переполнения. План разработки унифицированного контекстного уровня описан в [UAG_CONTEXT_MANAGEMENT_DESIGN.md](UAG_CONTEXT_MANAGEMENT_DESIGN.md).
